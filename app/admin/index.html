Playbook

One .md file holds everything that belongs to a company and a freelance platform. The simplest way is a prompt playbook: you write four prompts in plain language (company and roles, first message, chat logic, style) and the AI writes message 1 and every reply from them. The bot itself does not change. Import another file to use the bot for another company or platform. It applies to every profile at once and takes effect immediately. No restart is needed.

Import a playbook

Choose a .md file, or paste the text. Check reads it and shows problems and sample messages, and changes nothing. Use this playbook applies it. Messages that are already queued keep their old wording.

Try it (nothing is sent)

How to write the file

Prompt playbook (recommended). Start from Download prompt template. It has four sections. Write them in plain language:

  • ## Company and roles: everything the AI may say: the company, the roles, pay, application links, the assessment. The AI states nothing that is not here.
  • ## First message prompt: how message 1 must look (length, tone, what to mention, what to avoid).
  • ## Chat logic prompt: the steps of the conversation and what to do when the member answers, asks a question, gives a GitHub username, or declines. The AI can send a GitHub invitation (write "when the member sends a username, use the action invite_github") or close the chat.
  • ## Style rules (optional): how every message is written.

Fixed by the system, whatever the prompts say: the member's name is used in message 1 only; a pay figure or a link is sent only if it is written in the prompts; messages are short plain text; a refused message is rewritten and resent at once.

Fixed-text playbook. Start from Download fixed-text template for finer control. Every section is optional except Company and Roles. A section you leave out keeps the built-in text.

  • ## Company: Name: as the platform shows it, Website:, Careers page:, and ### About (what the company does. The AI may use only this).
  • ## Roles: one ### Role name each, with Type: developer (assessment on GitHub) or Type: business (application link), Rate: (inserted word for word in message 2), and for business roles Summary: (one sentence that starts with a verb), Interview:, Careers link:, and #### Details (the only facts the AI may give about the role).
  • ## First message, ## Introduction lines: rotating sentences for messages 1 and 2. Keep them free of words the platform's spam filter refuses.
  • ## Questions, ## Messages, ## Assessments: the question that ends each step, the fixed texts for steps 3 and 4, and the GitHub assessment for each developer role.
  • ## Writing rules, ## Role choice rules: the prompt rules for the AI.

Placeholders: {company} {website} {careers} {role} {url} {interview} {username} {repository}. The member's name is used in message 1 only, so {name} is not allowed anywhere else.

The file changes what the bot says. It does not change which platform the bot connects to. That is set by the MCP server URL in the server settings.
